- Behavior delivered:
  - Models. Every model has a UUID pk, an `organization` FK and an indexed `created_at` plus `updated_at`. The models are `Brand`, `Category` (optional parent), `Product` (family), `Variant` (SKU), `AttributeDefinition`/`AttributeValue` (typed; values carry `value_type` + `unit` + `is_published`), `Media` (path or https URL reference, `APPROVED`/`DRAFT`, alt text, never fetched) and `SourceReference` (staff-only provenance: source name, external id, source URL, `observed_at`, `is_synthetic`). There are no price, cost, stock or availability fields.
  - Units. Product and Variant `status` is `DRAFT`/`PUBLISHED`/`ARCHIVED`. Sales and stock units come from `piece, m, cm, kg, g, l`, and `quantity_increment` and `min_quantity` are `NUMERIC(14,3)`.
  - DB constraints:
    - SKU: unique per organization, stored uppercase (format check `^[A-Z0-9][A-Z0-9._-]{0,63}$`).
    - Units and status: known enum values only, plus `sales_unit = stock_unit`.
    - Quantities: increment > 0, min > 0, and `min_quantity % quantity_increment = 0`.
    - Attributes: typed-value check, exactly one target (product or variant), and unit only for DECIMAL definitions.
    - Media: the URL format is checked.
  - Same-organization integrity has two layers:
    - `save()` raises `ValidationError`.
    - Migration 0002 adds 12 composite foreign keys (`(fk_id, organization_id) → (id, organization_id)`; media `(variant_id, product_id) → variant(id, product_id)`; attribute `(definition_id, value_type, unit) → definition`). Bulk `update()` and raw SQL across organizations therefore fail too.
  - Quantity service: `catalog.quantities.validate_quantity` / `validate_variant_quantity`. A plain decimal string is accepted only if it is an exact multiple of the increment and ≥ `min_quantity`. Otherwise the result is 400 `INVALID_QUANTITY_INCREMENT` with `field_errors`; values are never rounded. Malformed input is 400 `VALIDATION_ERROR`. This is a pure service; there is no write endpoint.
  - Public endpoints (GET only, `AllowAny`, always public serializers): `GET /api/v1/catalog/products` (cursor; `category`, `brand` exact ids; `q` = case-insensitive name substring), `GET /catalog/products/{product_id}` (published variants embedded), `GET /catalog/variants/{variant_id}`, `GET /catalog/variants?sku=` (required; trimmed, uppercased, exact).
    - Scope: the actor's organization (guests: `DEFAULT_ORGANIZATION_SLUG`).
    - Visibility: only `PUBLISHED` products, and variants that are `PUBLISHED` with a `PUBLISHED` product. Only published attribute values and approved media are shown.
    - Unpublished, archived, other-organization, malformed and nonexistent ids all return the same 404 (body and headers), including for staff.
  - Staff view mechanism: separate endpoints `GET /api/v1/catalog/staff/products`, `/catalog/staff/products/{product_id}`, `/catalog/staff/variants?sku=`, `/catalog/staff/variants/{variant_id}`.
    - Authorization: `HasPermissionCodes` with `catalog.view_staff_fields`. Anonymous → 401. An authenticated actor without the code → 403 before any lookup, so it is id-independent. Otherwise the request is scoped to the actor's organization: other-organization ids → 404.
    - Content: every status, plus `status`, `stock_unit`, `supplier_code`, `internal_notes`, draft media, unpublished attributes (`is_published`), `source_references` and timestamps. There is an optional `status` filter on the product list.
  - Cursor ordering is public-only: `("name", "id")` for products and `("sku", "id")` for variants.
  - `seed_synthetic`: see "Seed usage" below.
- Migrations and rollback limits: `catalog.0001_initial`, `catalog.0002_same_organization_foreign_keys` (RunSQL with reverse `DROP CONSTRAINT`) and `catalog.0003_media_url_no_protocol_relative_source_url_https` (review fix: replaces the `catalog_media_url_format` CHECK with `^(/[^/\\\s]\S*|https://\S+)$` and adds `catalog_source_url_https`, empty or `^https://\S+$`). ### Seed usage

`$C run --rm --no-deps -e ALLOW_SYNTHETIC_SEED=1 api python manage.py seed_synthetic [--with-demo-users] [--data-dir DIR]` (Compose now mounts the data; add `-it` to see demo passwords).

- Guard (all three required, review fix): `settings.DEBUG is True` (local Compose with `.env.example`) or settings module `config.settings.test`; **and** the explicit opt-in `ALLOW_SYNTHETIC_SEED=1` (exactly `1`); **and** no non-synthetic `Organization` exists in the database at all. The first two are checked before any file is read (`CommandError` "Rechazado…"); the third inside the transaction (`select_for_update` over organizations), so nothing is written.
- Data: `tests/fixtures/synthetic/p1/catalog.json` is treated as data. It is type-checked, and the loader requires "SINTÉTICO" in organization, branch, brand, category, product (name + description), variant and media alt-text values. It also requires `example.test` emails, a source URL prefix that parses as `https://` with hostname `example.test` or `*.example.test` (no userinfo/port, review fix) and local `/catalog-media/sintetico/` media paths. All writes happen in one transaction; a SKU that the file moves to another product is a clean `SeedError` ("ya pertenece a otro producto"), and any unanticipated `IntegrityError` becomes a `SeedError` ("no se guardó nada") with full rollback.
- Contents:
  - Default organization (`DEFAULT_ORGANIZATION_SLUG`, `is_synthetic=True`): 2 branches, 3 brands, 6 categories and 9 products.
    - Published variants cover piece, m, cm, kg, g and l, including a kg variant with a 0.001 increment.
    - Hidden records: a draft product, an archived product, draft and archived variants, draft media and an unpublished attribute.
  - Second synthetic organization `otra-ferreteria-sintetica`: 2 products, one of them draft, plus a variant that reuses SKU `SIN-TOR-8X1`.
  - Every product and variant has a synthetic `SourceReference`.
- Idempotent: natural keys (slug, code/slug, SKU, source external id); a re-run creates no rows.
- `--with-demo-users` creates `admin.demo`, `empleado.central`, `empleado.norte`, `cliente.demo` and `admin.otra` (`@example.test`). Review fix: passwords are generated (`secrets.token_urlsafe(18)`, checked against the validators) and printed once **only when stdout is a TTY** (`docker compose run -it` or a local shell). With non-interactive stdout (CI, `-T`, piped, captured by Docker logs) the users are created with an unusable password and the command prints `docker compose run --rm -it api python manage.py changepassword <email>` for each. Passwords are never written to any file.
- Accepted local behavior (review item 6): the seed reuses existing `@example.test` accounts (password unchanged) and re-activates their synthetic role rows (`RoleAssignment`, `BranchMembership`, `CustomerProfile` for the file's organization). This is intended for local demo stacks only, which the guard enforces.

## Limitations and next action

- **Message registration.** Resolved by the coordinator: `INVALID_QUANTITY_INCREMENT` and its es-CR message live in `common/errors.py`. `common.schema`'s generic 400 description mentions `INVALID_CREDENTIALS`, so the catalog views use their own 400 description.
- **Data mount.** Resolved by the coordinator: `compose.yaml` mounts `tests/fixtures/synthetic` read-only, so plain `$C run --rm --no-deps api pytest` runs the seed tests. The contract export still mounts `contracts/` per command.
- **Seed guard.** Three conditions (local/test settings, `ALLOW_SYNTHETIC_SEED=1`, no non-synthetic organization). A deployment that sets both `DEBUG=True` and the opt-in on an empty database could still seed; that is a deliberate misconfiguration.
- **Demo passwords.** Non-interactive runs leave demo users without a usable password until `changepassword` is run interactively.
- **Media files.** Media URLs are references to `/catalog-media/sintetico/*.svg`, and no image files exist. P1-03 must render a placeholder (or the coordinator adds synthetic assets to the web app).
- **Search and OpenAPI wording.**
  - `q` is a plain `icontains` on the product name; fuzzy search, relevance and `(rank, id)` cursors are P2.
  - Category filtering is exact (no descendants).
  - Ordering by `name` follows the database collation.
  - Some English model/view docstrings appear as OpenAPI descriptions.
- **Out of scope.** No price, availability, stock or payment fields or endpoints (D07/D09 pending).
- **Next action.**
  - Coordinator acceptance of the review fix batch.
